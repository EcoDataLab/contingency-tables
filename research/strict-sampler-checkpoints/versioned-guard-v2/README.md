# Actual versioned guard measurement

The completed startup07 experiment ran the versioned v2 guard in a separate owned tools directory against the original authenticated sampler context. Both the original and v2 whole stat-only guards passed, and a separate complete dictionary validation matched all 131,021 admitted `(size, mtime_ns, ctime_ns, inode)` identities exactly. The original pinned runner and authenticator remain unchanged. This receipt contains no proof compilation, exporter, default-kernel replay or Comparator acceptance.

| Actual measured operation | Seconds |
| --- | ---: |
| Original whole stat-only Guard | 26.9243043 |
| Versioned v2 whole stat-only Guard | 1.1288378 |
| Separate complete three-observation identity validation | 0.4540280 |
| Versioned plan call with original admission/content checks | 83.9125675 |

The complete cache has 9,261,675,188 logical bytes. The v2 measurement preserves three distinct leaf observations: non-following stat for the link predicate, following stat for the regular-file predicate, and another following stat for final identity. It shares validated directory traversal. This actual whole-guard result is separate from the earlier [single-stat prototype measurement](../snapshot-comparison-v1/); the historical 0.198-second prototype walk is not v2 whole-guard timing.

Its source header records the earlier preparation state; this receipt records the subsequently authorized bounded execution in a separate directory, without replacing the original runner.

[source/guard_benchmark.py](source/guard_benchmark.py) invokes the versioned plan against the original-authenticated runtime, constructs the original Guard using identical admitted attributes, and times both actual guards once under the shared exclusive lock. It then separately validates a complete v2 dictionary against admission. All comparisons are exact dictionaries, not samples or digest equality alone. Measurement order was original guard, v2 guard, then separate identity validation. Nine bounded local mutation/order/cleanup and unchanged-source checks and a separate read-only source/receipt review preceded this experiment; neither is a proof of arbitrary filesystem race equivalence.

The guarantee assumes trusted supervision maintains an exclusive quiet checking/cache context. Package caches are within the sandbox's writable `.lake` hierarchy; the lock coordinates cooperating runners. Neither guard provides continuous protection against a deeper namespace substitution consumed by a child and restored before its next boundary check. The candidate adds stronger directory-drift rejection during traversal but does not claim universal concurrent-race/error indistinguishability. Persistent selected-file drift and the existing complete content/keyset boundaries remain checked. [review-and-contract.json](review-and-contract.json) records this practical trust boundary explicitly.

The guest used one vCPU, 8 GiB RAM, explicit `whpx,kernel-irqchip=off`, no NIC, no swap and a fresh 80 GiB child. Installation, real sandbox preflight, original authentication and versioned plan/measurements returned zero. Stage times were 1.607, 0.428, 160.362 and 112.719 seconds; supervised VM lifetime was 373.954 seconds. Individual measurement ceilings were 900 seconds and aggregate ceiling 1,800 seconds. No soft-lockup warnings or QEMU stderr were recorded. The supervisor terminated and reaped its owned VM after collection, QEMU returned 1, all five retained image/tool pins remained equal and the process inventory was clear at collection.
