## Semantic checks

**Terminal correction on supplied codes.** The computational definitions receive a full retained source row-view matrix code, explicit ordered defect labels, margin lists and reserved coin bits. They apply the actual repair entry formula, inspect every repaired large cell for padding, unpad, compute the allowance from literal small-row/column counts, count inverse labels on the ordinary output code, and use the established clipped integer threshold and bit decoder. Padding failure remains `none` and ignores its suffix. The pointwise equality theorem compares this program with `terminalBitCorrection` on the semantic encoding of an actual retained joint and its actual ordered labels. The Nat/Int transfer argument correctly accounts for truncated natural subtraction on these actual inputs. List iteration preserves the full rectangle and includes the large crossing.

This theorem supplies no feasibility or sampling guarantee on arbitrary malformed matrix/label codes. It does not extract the full retained view or defect labels from an upstream encoded residual draw. Those values are supplied through proof-side semantic encoders in the correspondence statement.

**Ordered raw neighbor selection.** The computational definitions decode integer bits, perform capped interval rejection using disjoint reserved blocks, index the existing raw code-neighbor list and return an optional raw state-view code. The exact bit-order bridge identifies the concrete decoder with the established finite-word integer decoder. Total validity of code neighbors and exact re-encoding after semantic decoding establish full ordered-list equality, preserving positions and multiplicities. The lookup theorem includes all natural indices, including unused/out-of-range slots. Interval rejection occurs before lookup; an accepted unused slot returns `none` without another interval trial, exactly matching the rational-clock proposal. Exhaustion and holding therefore preserve `none`. Runtime definitions do not invoke the semantic state decoder.

The pointwise proposal theorem is for actual encoded state/check data and the actual denominator. Arbitrary malformed check data does not acquire typed-state validity or an accuracy guarantee. This is a raw proposal interface, separate from encoded acceptance, repeated trace evolution and complete joint sampling.

**Initial profile code from margins.** The ordinary definitions pad a greedy fallback matrix, search the finite support-label list internally, perform the two inverse transfers, and emit the catalog-ordered profile code. The first list is the retained row view; the second is the capacity complement of the retained column view. On small catalog cells capacity is exactly U, so the explicit `U - columnView` representation matches `computedStateCode`. The transfer uses integer subtraction before conversion to naturals, including coincident source/receiver cases. The equal-total proof is an erased precondition; no feasible table, label pair or actual start is supplied by the caller. On reference inputs, the theorem states that the option result is `some` of the actual initialized state's profile code. This closes a computational initial-profile-code interface. It does not construct a complete retained completion/joint code, or validate unequal-total inputs at runtime.

**Retained source reconstruction.** The ordinary joint-code definitions reconstruct small row-view entries from the catalog-ordered state code and large entries from the residual completion matrix in the existing large-line order. Output padding is deliberately zero during this reconstruction, so dense entries below L are retained until the later actual repair and padding test. Exact source reconstruction is proved on actual state/residual codes. A further equality identifies the frozen executable residual draw with that same residual block. This removes the need to supply a chosen full source matrix to terminal correction. The draw statement still forms its coarse completion margins semantically, and ordered defect labels remain supplied through their actual semantic encoder. It does not yet derive every upstream completion input or extract labels from arbitrary raw state data.

No source-semantic defect was found in the inspected definitions and correspondence statements. Failed candidates remain distinct from successfully compiled source hashes.
